# macOS USB DAC Validator

Run `./build.sh` on macOS with Xcode command-line tools, Rust and a C compiler installed. It builds an Apple Silicon unsandboxed `.app` and a drag-to-install DMG in `build/` for macOS 12 or later; install the aarch64-apple-darwin Rust target first. The worker links vendored libusb. The app uses the direct USB driver, not CoreAudio. Set `SIGNING_IDENTITY` to a Developer ID Application identity to sign the app, worker and DMG with the hardened runtime and a secure timestamp; without it they are ad hoc signed. Also set `NOTARY_KEY_PATH` (an App Store Connect API `.p8` key), `NOTARY_KEY_ID` and `NOTARY_ISSUER_ID` to notarize and staple the DMG. Release builds do both, with the identity and key from repository secrets.

Remove headphones and mute or disconnect the amplifier before starting. Start capture first, then connect one DAC. The test may emit DoP marker noise if the device does not decode DoP. The ZIP is generated on completion, cancellation or a handled failure; use **Save diagnostics** to choose its destination. Reports contain device identifiers and debug logs.

The **Include source-backed compatibility modes** option is enabled by default for validator runs. It selects the library's `SourceBacked` quirk policy, which can expose device-specific modes supported by source evidence even when they have not been verified on this host. Clear the option to use the library's strict `VerifiedOnly` default. The chosen policy is saved in the ZIP, including when the run ends before a DAC is opened. The worker also accepts `--verified-only` after the capture-directory argument for command-line runs.

Open the app as a regular user. Each **Start capture** requests macOS administrator approval before establishing the USB baseline and asking for the DAC. The app remains unprivileged; an approved, one-shot worker performs direct USB diagnostics and exits after the run. The worker creates its own private system temporary directory and sends the archive to the app over a local socket. Both ends check the peer user ID. Denying or cancelling approval leaves a partial diagnostic archive available to save. If the app or worker exits unexpectedly, recovery contains only evidence the app actually received; it may be incomplete.

macOS may already own a DAC through its USB audio driver. The worker attempts an ordinary claim first. After an ownership or access claim failure, the app automatically permits libusb to capture the entire selected device from its kernel driver, including its other interfaces. Connect only the intended device. The archive records the effective user ID, claim and capture outcomes, and hand-back logs. The app does not disable system security or install a persistent helper. Unplug and reconnect the DAC if macOS does not restore the audio route after a captured run.

The standalone worker retains its existing command-line capture-directory mode; it does not request authorization itself, and whole-device capture there still requires the `--allow-capture` flag. Launch it with the permissions required by the intended device when using that mode.

On 27 November 2026, an administrator-authorized run on macOS 15.8.3 arm64 tested an iBasso DC04 Ultra (`0661:0883`). The ordinary interface claim returned access denied; whole-device capture and reclaim succeeded. All 50 exact USB playback cases passed, including 30 PCM, 8 native DSD and 12 DoP carrier cases. All 188 exact admission probes returned expected rejections. The report recorded 41 USB-verified converted fallbacks and 159 unavailable fallbacks, and session close returned `Ok(())`. DoP decoder lock and analog output were not observed. The evidence archive is `macOS-DC04U-admin-whole-capture-playback.zip`.
