# USB audio feedback engineering handover

Build the implicit feedback path through the public Android and Rust APIs, review and validate that batch, then implement the three explicit feedback corrections in order. Use GPT‑6.1 Sol medium implementers. The lead reviews the integrated code and owns verification at each checkpoint.

Read [the implementation design](usb-audio-feedback.md) and the supplied `usb-feedback-handover/HANDOVER.md`, `GUIDE.md` and `reference/src/{classify,implicit,explicit}.rs`. The executable reference establishes the IN-first, per-transfer queue and explicit rate decoding. The design records changes backed by USB-IF, Linux ALSA and the Linux UAC2 gadget. Write independent MIT source against the existing driver.

## Batch 1 — implicit feedback

**Discovery and topology.** Own the descriptor scan, candidate selection, clock proof and claim preflight. Add an internal `ImplicitFeedbackSource` to the selected OUT candidate carrying the source interface, alt, endpoint, IN frame stride, service interval and byte capacity. Keep a single chosen mechanism. Distinguish valid explicit, well-founded implicit, opted-in nominal async and malformed or unsupported AS geometry. Require shared UAC2 audio function, an actual resolved clock route, equal effective wire rate and equal service interval. Support a linked or marked source and structurally proven plain async IN. Preserve strict pair selection under alternate changes, incomplete topology and ambiguity. Treat UAC1 and vendor mappings as evidence-backed quirks. Verify the matching rate and USB capacity before committing the candidate. Include real-path tests wherever descriptor material permits and pure pairing cases for malformed or ambiguous inputs.

**Transfer ownership and playback.** Own the stream-open and worker path, ISO slots and runtime health. Activate both streaming interfaces when required, submit IN first after producer prime, and match each fresh, complete IN frame-count pattern with a ready OUT slot. Process patterns in submission order, use bounded preallocated storage, and convert IN bytes through whole IN frames into OUT bytes. Leave PCM and DSD encoding, ring accounting, marker state, volume and delivery accounting in the existing payload path. Keep IN feedback running across pause, drain and seek/flush. Surface late, invalid, empty and overflow cases with the startup and running rules in the design. Suppress the bit-perfect verdict while implicit feedback is unlocked. Drain both pools before disposing of buffers or resetting alternates. Test startup, ordering, counters, mixed strides, flush, loss, cancellation, detach and restart without introducing a second USB event owner.

**Android and public surface.** Keep Android claim ownership in Kotlin. Use a read-only Rust preflight after base claims to identify only plausible capture interfaces and record actual claimed and unavailable sources. Verify the active configuration and claim subset in native code. Preserve viable OUT routes if an unrelated optional claim fails. Wire the selected endpoint tuple from Rust through JNI and Kotlin as `implicit_feedback`. Keep legacy explicit capability and endpoint fields. Carry live health separately from selected pacing and preserve the typed unsupported, claim, transfer and detach codes. Document the optional feedback disable setting and capture interface lifetime. Cover Kotlin claims, native schema and public fallback behavior.

**Integration contract.** Send candidate and preflight signatures to the related implementers before wiring callers. Reserve shared files or hand them off explicitly. Lead review must trace normal public entry points through claim, negotiation, worker and stop. Confirm the preflight never starts capture, selected format identifies the source, OUT submission consumes exactly one fresh validated pattern, and a handle cannot be released to a new owner while transfers remain outstanding.

## Batch 2 — explicit feedback

Start this batch when the implicit changes have reached their integrated review checkpoint. Preserve its clock, flush, payload and cancellation invariants.

1. **Newest valid report.** In `transport/iso.rs`, use each packet's true status, requested offset and actual length. Scan polls in wire order, count successful empty polls separately and apply the most recent report that passes length, decode and rate checks. A newer malformed report cannot mask an earlier valid report. Test oversized data, bad packet status, empty success, malformed trailing polls and a later valid replacement. [USB 2.0 §5.12.4.2](https://www.usb.org/document-library/usb-20-specification)
2. **Largest packet bound.** Convert USB base-time units to OUT service cadence before checking the report. Validate `ceil(frames_per_out_service) <= max_packet_bytes / out_stride` before committing any rate to the scheduler. Preserve fractional phase and the existing nominal plausibility window. Add a 48.05-to-49 regression, independent feedback and OUT intervals, both standard lengths and a Linux gadget per-service vector with a trace-backed compatibility rule. Honor existing device compatibility cases with narrowly defined decoding rather than auto-shifting unknown payloads. [Linux UAC2 gadget](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/drivers/usb/gadget/function/u_audio.c#L100-L147)
3. **Bounded feedback loss.** Wire explicit feedback through the live lock/stale contract. Limit initial nominal priming and recoverable report outages by a cadence-aware deadline. Initial allocation and submission failures must not become silent nominal playback. Clear lock and the bit-perfect verdict at stale, emit the existing stale event on transition, and fail the stream with a typed error if the deadline expires. Keep cancellation and detach distinct. Test no first report, empty polls, recovery before failure, timeout, first-submit failure and detach. Use the current single batched slot and worker with additional slots reserved for a measured scheduling issue.

## Verification and hand-back

- Finish connected production and test changes in each batch before running checks. Reuse existing test modules and CI gates. Keep fixtures, runners, observers and validation frameworks unchanged.
- Run `cargo test --workspace --locked`, the CI Android target check, the existing AAR/sample build and Kotlin unit tests, and the SDK snippet check when documentation changes. Examine actual tests for the behavior they claim.
- Use a focused Android acceptance session only when a matching USB DAC is available. The implicit case needs an actual paired IN source, and explicit regression needs a known-working explicit DAC or a programmable device. Confirm the clock route and observed packet sizes, verify stop/restart and flush, and preserve results before further modifications. Report unavailable hardware coverage separately from deterministic build and test evidence.
- Keep the work local for review unless publishing is authorized. Record any narrowed compatibility claim with the hardware or descriptor evidence needed to expand it.
