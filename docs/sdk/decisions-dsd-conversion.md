# Explicit DSD conversion

The input contract is the native stream contract: chronological bytes interleaved one per channel, with the oldest bit in bit 7. DoP input and arbitrary PCM bytes are not accepted by these adapters. The DoP adapter requires independent proof that the downstream route decodes DoP. It packs each pair as `[later, earlier, marker]` (or `[0, later, earlier, marker]` in a four-byte slot), alternates markers per frame, and holds at most one carrier frame. One incomplete source byte-frame is retained across writes; drain rejects an incomplete final pair. A separate DoP input adapter validates common 05/FA markers and alternation, rejects nonzero padding, unpacks to the same native byte contract, and reports positions in carrier frames.

The PCM converter is always lossy. It accepts DSD64, DSD128, and DSD256 with one to eight channels. A 512-tap Blackman-windowed low-pass decimates the 1-bit input by 16, then the existing high-quality PCM resampler and quantizer produce the requested PCM format. The first-stage passband and stopband are tested, and the second stage has its own quality tests. History and filter phase survive chunk boundaries; flush resets them. At EOS a partial final pair is padded with DSD silence and the finite filter tail is emitted; the position is capped at the actual input count. The adapter exposes filter latency as source byte-frames, keeps playback positions in source time, and reports the outstanding source frames as latency; quantization and filtering are not bit-perfect and the adapter says so. Outputs and input are bounded; output backpressure leaves pending data in the adapter.

The DSD→PCM adapter accepts the caller's conversion quality, headroom, narrowing, and dither seed. PCM source-layout overrides are rejected because DSD has its own byte contract. Headroom is applied exactly once whether or not the PCM stage changes rate. PCM saturation counts are available through the adapter and through the DoP input wrapper when it owns that adapter.
