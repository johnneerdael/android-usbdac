# Explicit DSD conversion

The input contract is the native stream contract: chronological bytes interleaved one per channel, with the oldest bit in bit 7. DoP input and arbitrary PCM bytes are not accepted by these adapters. The DoP adapter requires independent proof that the downstream route decodes DoP. It packs each pair as `[later, earlier, marker]` (or `[0, later, earlier, marker]` in a four-byte slot), alternates markers per frame, and holds at most one carrier frame. One incomplete source byte-frame is retained across writes; drain rejects an incomplete final pair. A separate DoP input adapter validates common 05/FA markers and alternation, rejects nonzero padding, unpacks to the same native byte contract, and reports positions in carrier frames.

The PCM converter is always lossy. Standalone `DsdPcmOutput` and Rust `DsdPcmConverter` apply configured headroom exactly once: at the first stage when no PCM resampling is needed, otherwise after the PCM resampler. The automatic selector uses unity gain when its PCM target equals the DSD intermediate rate (`dsdBitRate / 16`), and applies configured headroom when those rates differ. Set `headroomDb = 0.0` (Rust `headroom_db`) for standalone unity; this does not make conversion lossless. The -3.5 dB default covers a measured PCM square-wave overshoot fixture, not every signal or intersample peak. The post-dither integer-quantizer saturation counter includes rounding and dither clamps, and cannot guarantee absence of intersample peaks. It accepts DSD64, DSD128, and DSD256 with one to eight channels. A 512-tap Blackman-windowed low-pass decimates the 1-bit input by 16, then the existing high-quality PCM resampler and quantizer produce the requested PCM format. The first-stage coefficient test checks gain within 0.1% at 0.01 cycles per DSD bit and response below 0.001 (-60 dB relative to unity) at 200 points from 0.03125 to 0.5 cycles per bit. At DSD64 those points span 88.2 kHz to 1.4112 MHz, an ultrasonic first-stage stopband rather than an audible-band claim. A separate full-chain DSD64-to-44.1 kHz float fixture injects a half-scale 30 kHz tone and asserts its 14.1 kHz alias amplitude is below 0.002 (about -54 dBFS, or -48 dB relative to that input tone); its 1,378.125 Hz in-band tone remains between 0.47 and 0.53 amplitude. These are bounded software fixtures, not a universal ultrasonic rejection guarantee. The second PCM resampler has its own quality tests. History and filter phase survive chunk boundaries; flush resets them. At EOS a partial final pair is padded with DSD silence and the finite filter tail is emitted; the position is capped at the actual input count. The adapter exposes filter latency as source byte-frames, keeps playback positions in source time, and reports the outstanding source frames as latency; quantization and filtering are not bit-perfect and the adapter says so. Outputs and input are bounded; output backpressure leaves pending data in the adapter.

The DSD→PCM adapter accepts the caller's conversion quality, headroom, narrowing, and dither seed. PCM source-layout overrides are rejected because DSD has its own byte contract. Standalone conversion applies its configured headroom once whether or not the PCM stage changes rate; the selector’s equal-intermediate-rate unity policy is described above. PCM saturation counts are available through the adapter and through the DoP input wrapper when it owns that adapter.
